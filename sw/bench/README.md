# Benchmark kernels

Small self-checking programs (exit code 0 is a pass). Each is written so
that one component of the processor changes its cycle count visibly, or,
for the kernels that show a limit, visibly does not. Each runs 16,000 to
46,000 instructions. They are small on purpose: the cause of every cycle
count can be worked out from the counters.

| Kernel | What it does | What it shows |
| --- | --- | --- |
| `loop_nest` | A 12 x 12 x 32 loop nest | Branch prediction removes nearly every flush |
| `branch_alt` | A branch that alternates taken and not taken | The limit of a 2-bit counter: half of them wrong |
| `calls` | Calls, returns and indirect jumps; one function has two callers | The BTB hides jumps, except the return whose target changes |
| `bsearch` | 250 binary searches with pseudo-random keys | Data-dependent branches bound any predictor |
| `array_sum` | 8 passes over a 16 KiB array | Spatial locality; prefetching hides the line misses |
| `stride_walk` | One load per 64 bytes over 32 KiB | A stride prefetcher helps; next-line fetches only unused lines |
| `list_walk` | Pointer chasing through a scrambled 256-node list | Nothing to learn: the limit of prefetching |
| `conflict` | Two arrays 4096 bytes apart, read alternately | In a direct-mapped cache each access replaces the line the next one needs; two ways hold both |
| `ilp_chains` | Four independent chains of operations per iteration | A wide out-of-order core runs them side by side |
| `dep_chain` | The same work as one serial chain | No parallelism to find: IPC stays near 1 |
| `miss_indep` | One missing load and 8 independent operations per iteration | Out-of-order execution works during the miss |
| `code_walk` | Straight-line code larger than the instruction cache (generated by `gen_code_walk.py`) | Instruction-cache misses and instruction prefetching |
| `memcpy`, `sieve`, `matadd` | Ordinary loops | The overall trend |
| `lru_fifo` | Three lines used every round, a fourth place shared by many | LRU keeps the three; FIFO evicts them in turn |
| `ways_plus_one` | Five lines in turn in a set that holds four | LRU's worst case: it never hits, random replacement does |
| `fill` | A 16 KiB array written end to end | Allocating on a write miss against not allocating; merging in the write buffer |
| `store_hot` | Thousands of stores to two lines | Write-back against write-through, with and without a write buffer |
| `ws_walk` | One load per line over a working set of adjustable size | The staircase: a load's cost depends on which cache level the data fits in |
| `incl_victim` | A constantly used line that the second-level cache never sees again | The cost of inclusion; what a victim buffer saves |

The first fifteen are measured on every machine. `lru_fifo`,
`ways_plus_one`, `fill` and `store_hot` are measured on the cache-policy
machines, and `ws_walk` and `incl_victim` on the cache hierarchy.
[docs/RESULTS.md](../../docs/RESULTS.md) has the numbers.

```text
python tools/rvsim.py sw/bench/loop_nest.S     # run one kernel on the golden model
python tools/regress.py bench                  # cycle counts on every machine
```
